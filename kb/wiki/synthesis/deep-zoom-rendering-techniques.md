# Build a single-reference, skip-table, float32 renderer

As of 2026 the state of the art in fast deep zoom is a settled pipeline. One arbitrary-precision reference orbit is computed on the CPU, usually at a minibrot nucleus. Every pixel runs a low-precision perturbed delta on the GPU. **Zhuoran's rebasing (2021)** makes glitches impossible by construction, so one reference serves the whole image, and a precomputed **linear-approximation skip table** (mathr's binary-tree BLA, or Imagina's period-aligned LA with its "AT" minibrot shortcut) skips most of the iterations. Series approximation, Pauldelbrot multi-reference glitch correction and knighty's nanoMB are now legacy. Every renderer still being developed (Fraktaler 3, Imagina, FractalShark, Fractal Zoomer) uses BLA/LA plus rebasing, and the KF2+ author himself points users away from his SA-based program ([mathr KF page](../sources/kf-page.md)). For almondbread the main constraint is the float32-only Apple GPU. Rebasing and BLA both work in float32, with **ε = 2⁻²⁴ in the skip radii**. Range is the real problem, not precision: squared norms underflow near 1e-19 and deltas near 1e-38, so past about 1e-25 to 1e-30 you need rescaled float32 deltas with floatexp coefficients. The pieces that set speed and robustness are known, and two 2026 Swift/Metal hobby projects already show the basic stack runs on Apple Silicon. The remaining work is engineering: chunked dispatches under the macOS watchdog, specialised kernels per number type, verification tooling, and then the Imagina-style LA/AT upgrade that wins at minibrot depths with millions of iterations.

## Rebasing turned perturbation into a one-reference algorithm

The base formula has not changed since K.I. Martin's SuperFractalThing. Iterate `Z_{m+1} = Z_m² + C` in high precision and, per pixel, `z_{n+1} = 2Z_m z_n + z_n² + c` in hardware floats. The delta form must be written symbolically. Computing `(Z+z)² + (C+c)` directly and then subtracting destroys the information through catastrophic absorption ([mathr 2021](../sources/mathr-deep-zoom-theory.md)). Until 2021 the weak point was glitches. When a pixel orbit passes near the critical point 0 while the reference does not, the delta stops being small relative to the full value. Pauldelbrot's test `|Z+z|² < G·|Z|²`, with G between 1e-2 and 1e-8, detected these pixels, and renderers re-rendered them against new references, recursively. KF capped this at 10,000 references and warned that "special locations can produce endless references" ([KF2+ manual](../sources/kf-manual.md)).

Zhuoran's rebasing removes the problem instead of detecting it. **After each step, if `|Z_m + z_n| < |z_n|`, or the reference runs out, set `z ← Z_m + z` and `m ← 0`** ([mathr Deep Zoom](../sources/mathr-deep-zoom-page.md)). The reference starts at `Z_0 = 0`, which is exactly the critical point, so the new delta equals the full value with no cancellation, and the delta can never dominate. Two consequences matter for design. First, the reference no longer has to be as long as the deepest pixel's orbit. A pixel that outruns it simply wraps back to the start. Second, the pixel iteration count `n` and the reference index `m` diverge, so a kernel must track both. Multiple critical points or hybrid formulas need one reference per critical point or per hybrid phase. A four-phase hybrid such as (M,BS,M,M) needs four, and as of 2022 only the single-critical-point case was implemented anywhere ([mathr 2022](../sources/mathr-deep-zoom-theory-again.md)). KF 2.15.5 shipped the single-reference method enabled by default, with the honest caveat that it "does not cure all glitches" for every hybrid ([KF2+ manual](../sources/kf-manual.md)). For power-2 Mandelbrot it is complete. Keep Pauldelbrot's test only as a debug overlay to catch float32 failures.

The one documented float32 rebasing failure is instructive. A WebGPU renderer stored an extended-range value with the magnitude in the mantissa and exponent 0, and compared exponents first in the rebase test. At a minibrot nucleus rebasing never fired, and the frame rendered black ([Desarso/mandelbrot-webgpu](../sources/desarso-mandelbrot-webgpu-readme.md)). Every rebase and escape comparison on an extended-range type has to compare normalised magnitudes.

### Reference selection: use the nucleus, found by ball period and Newton

Because rebasing wraps on exhaustion, the best reference is the nucleus of the lowest-period minibrot in or near the view. Its orbit is exactly periodic (`Z_p = 0`), so only p high-precision iterations are needed, and wrapping at m = p does not change the value. The recipe is KF's default. Find the period with the **ball method** (knighty/gerrit interval arithmetic, which replaced Munafo's box/Jordan-curve method as default and "works much better in skewed locations"), then refine with Newton on `z_p(c) = 0`, using the iterated `L_p` and `L_p'` without expanding polynomials ([KF2+ manual](../sources/kf-manual.md); [mrob Newton-Raphson](../sources/muency-newton-raphson.md)). Atom domains give a cheap candidate period: the iteration where `|Z_n|` hits its minimum ([mrob Atom domain](../sources/muency-atom-domain.md)). The view centre still works as a fallback, but it costs maxIter high-precision iterations. The exact ball recurrence was not verified against knighty's note, so test it against the box method before relying on it.

On precision, no fetched source states the formula KF or Fraktaler uses. A sound rule of thumb (my inference) is bits ≈ log₂(magnification) + log₂(image width) + 32 to 64 guard bits, so about 380 bits at 1e100. The orbit is serial. Speedups come from fewer iterations (the periodic nucleus), faster squaring and smaller storage. GMP runs very well on M1, where "almost every inner loop runs at < 1 cycle/limb" and the M1 placed #2 on GMPbench in 2020 ([gmp-discuss](../sources/gmp-m1-discuss.md)). Fixed-size multiplication kernels beat `mpn_mul_basecase` by up to 80% at 8 limbs on M1 ([gmp-devel 2024](../sources/gmp-fixed-size-mul.md)). FractalShark's MT3 pattern (two threads squaring, one coordinating) is the known way to parallelise one iteration ([FractalShark](../sources/fractalshark-readme.md)). Its GPU NTT reference orbit only pays off past about 1e10000, and Apple's int32 multiply runs at 1/8 the fp32 FMA rate ([metal-benchmarks](../sources/metal-benchmarks-readme.md)). **A Metal bignum is therefore not worth building**. Keep the reference on the P-cores.

## Period-aligned linear approximation is the fastest skip method

Iteration skipping is where the order-of-magnitude wins are. Classic series approximation fits `z_n = Σ A_{n,k} c^k` from coefficients computed along the reference, and picks a global skip count with probe points. It has no rigorous error bound ([mathr 2021](../sources/mathr-deep-zoom-theory.md)), the worst pixel limits every pixel, and abs-folding formulas allow "only a few iterations" of skip. **BLA replaces it.** Each table entry approximates l steps as `z_{m+l} = A·z_m + B·c`, valid while `|z| < R`. Single steps have `A = 2Z`, `B = 1`, and radius `r = max(0, ε(|Z| − max|c|)/(2|Z| + 1))`, with ε the hardware precision, **2⁻²⁴ for float32**, and |Z| halved for safety. Entries merge pairwise: `A = A_y A_x`, `B = A_y B_x + B_y`, `R = min(R_x, max(0, (R_y − |B_x|·max|c|)/|A_x|))`. This gives a binary tree of about 2M entries for an M-iteration reference, starting at iteration 1 because iteration 0 has radius 0 ([mathr 2022](../sources/mathr-deep-zoom-theory-again.md)). Per pixel, take the longest valid skip, else one perturbation step, then the rebase check. mathr calls the radius derivation "a bit handwavy", and no proof exists.

Measured gains are large but come from one CPU JavaScript implementation. On an M1, Very Plotter's BLA beat perturbation+SA by **10.2× at 2.9e89 (350k iterations) and 36.2× at 4.99e152 (2M iterations)**, skipping about 989k of 1.2M iterations per pixel at 5.6e227. At one floatexp location (9.5e693), though, SA won by about 1.7×, and ε had to be lowered to about 1e-122 there ([Phil Thompson 2023](../sources/philthompson-bla.md)). That counter-example comes from a naïve tree with a tuned ε, not from a modern LA. It is a warning that radius tuning matters, not a reason to implement SA.

Imagina's evaluator is the real state of the art, and the code is more precise than any write-up. It is **a hierarchy of up to 256 stages whose step boundaries follow the reference's near-returns to 0**, coarsening about 16× per stage when no period is found. Each LA step does its first iteration non-linearly and the rest linearly: `dz' = ZCoeff·(dz·(2Z + dz)) + CCoeff·dc`. Validity is tested on `‖dz(2Z+dz)‖∞ < LAThreshold` and `‖dc‖∞ < LAThresholdC`, using Chebyshev norms and a threshold scale of 2⁻²⁴. Lookup is O(1): walk the current stage's macro-steps in order, and drop to the finer stage when a step is invalid. Derivatives for distance estimation propagate through LA steps almost for free. Coefficients are stored as double when the range allows and as FloatExp otherwise, decided per stage ([Imagina HInfLAEvaluator.cpp](../sources/imagina-hinfla-evaluator.md)). When the reference is periodic, the **AT** step maps a pixel into renormalised coordinates around the minibrot and iterates plain `z ← z² + c` in low precision. Each step there counts as one full period of reference iterations until the pixel escapes the AT radius ([Imagina HInfLAEvaluator.h](../sources/imagina-hinfla-evaluator.md)). AT is the robust descendant of nanoMB, and it is the single largest win for minibrot zooms with 1e6 to 1e9 iterations. FractalShark's "HDRx32 LAv2" CUDA kernels come from this lineage via Fractal Zoomer, and they use 52-byte rows of float plus exponent ([FractalShark](../sources/fractalshark-readme.md)).

My reading of why LA beats the tree has three parts. The non-linear first step removes the radius-0 wall at the reference's near-zero points. Stage boundaries line up with where rebasing happens, so a pixel can repeatedly "skip one period, rebase" instead of falling back to fine levels at every period boundary. And the |c| dependence lives in a separate threshold rather than being baked into R. The BLA tree, in contrast, is built for the image's max|c| and must be rebuilt when the framing changes. Fraktaler 3 notes that BLA reuse across a zoom-out is "not generally applicable" ([Fraktaler 3](../sources/fraktaler-3-site.md)). One caveat runs the other way. **The BLA tree generalises to Burning Ship, Mandelbar and hybrids** through 2×2 real Jacobians with singular-value radii, capped by |X| and |Y| for abs formulas ([mathr Deep Zoom](../sources/mathr-deep-zoom-page.md)). Imagina's LA is Mandelbrot-specific. No published benchmark compares Imagina LA against BLA on a GPU. Imagina and Fraktaler 3 are AGPL, so almondbread may implement these algorithms from description but must not copy their code.

## Range, not precision, is float32's binding constraint

mathr states it plainly: "double (53-bit) is more than enough for perturbed orbits; single (24-bit) can also work", and single "underflows below about 1e-38" ([mathr 2021](../sources/mathr-deep-zoom-theory.md)). The practical floor sits much higher than 1e-38, because rebase and escape tests use squared norms, which underflow near √1e-38 ≈ 1e-19. The float32 WebGPU renderer hands over from plain f32 deltas at 1e-25 units per pixel, "thirteen decades above the f32 floor". Its older WebGL path, with plain deltas, stopped at about 1e-34 ([Desarso/mandelbrot-webgpu](../sources/desarso-mandelbrot-webgpu-readme.md)). Apple denormal behaviour was not found in any source, so assume flush-to-zero.

The way past the floor is **rescaled iteration**. Substitute `z = S·w` and `c = S·d` to get `w → 2Zw + S·w² + d`, with S chosen so |w| ≈ 1. Renormalise only "every few hundred iterations", drop the `S·w²` term when S underflows, and do **full floatexp iterations only when |Z| is tiny** ([mathr 2021](../sources/mathr-deep-zoom-theory.md)). The hot path stays as pure float32 FMA. Because rebasing can only trigger when |Z_m| is comparable to |z|, which is exactly when the floatexp branch runs, rebasing and rescaling fit together cleanly (my inference). KF's rescaled perturbation is "arbitrarily deep", and rescaled SA ran about 30% faster than all-floatexp ([KF2+ manual](../sources/kf-manual.md)). BLA and LA coefficients are a separate issue. Over long skips they reach about 1e700, which overflows even double and turns radii into NaN ([Desarso/mandelbrot-webgpu](../sources/desarso-mandelbrot-webgpu-readme.md)). In float32 they overflow far sooner, so **coefficients and radii need per-quantity floatexp** once the zoom is past about 1e-30. One shared exponent per record fails, because ZCoeff grows exponentially while Ref stays O(1). The table below is my synthesis of the cited thresholds.

| Pixel spacing | Delta type | Skip table storage |
|---|---|---|
| > ~1e-5 | direct float32, no reference | none |
| ~1e-5 to ~1e-25 | float32 perturbation, Chebyshev or max-abs norms in tests | float32 |
| < ~1e-25 (unbounded) | rescaled float32, floatexp scale, floatexp "full" steps near \|Z\|≈0 and at rebases | floatexp per coefficient and per radius |
| any depth, verification or artefact repair | float-float (2×f32) mantissa plus exponent, FractalShark's "2×32+exp" | floatexp |

Double-float is a precision fix, not a range fix. It gives about 48 bits with fp32 exponent range ([luma.gl](../sources/luma-gl-gpu-precision.md)). It matters in two places: directly rendering the shallow band before perturbation pays off, and as a repair mode if long-orbit float32 rounding shows as speckle near minibrots. FractalShark reports its 2×32+exponent type gives "substantially higher performance on consumer GPUs with only a modest loss of precision" ([FractalShark](../sources/fractalshark-readme.md)). The Metal-specific danger is the compiler. TwoSum and TwoProd rely on exact rounding events, and "a compiler that reassociates the expression can therefore erase the information". luma.gl switches to an integer-controlled path on Apple adapters for exactly this reason ([luma.gl](../sources/luma-gl-gpu-precision.md)). Integer multiply is 1/8 rate on Apple GPUs, so the right move is fma-based float-float compiled with `MTLCompileOptions.mathMode = .safe` for that library only, plus a startup known-answer test (does TwoSum(1, 1e-8) keep a nonzero low limb?). The `mathMode` semantics could not be verified from Apple's docs, which did not render.

KF itself disabled single precision by default because of "undetected glitches at some locations" ([KF2+ manual](../sources/kf-manual.md)), and no 2023–2026 study quantifies float32 versus float64 perturbation error. That gap is the biggest technical risk in the whole plan. It must be addressed with tooling, not assumed away. Build a CPU double/floatexp reference renderer for tile diffs, a "skip table off" pixel-diff mode, and a high-precision oracle, which is exactly the verification set the WebGPU project found necessary.

## Apple GPU engineering decides whether theory becomes frame rate

M1-class GPUs run 256 fp32 FMAs per core-cycle in 32-wide SIMD groups. They have no fp64: emulated FMA costs about 1/68 of fp32. Integer multiply runs at 32 per core-cycle, and "ALU utilization maxes out at 24 simds/core" ([metal-benchmarks](../sources/metal-benchmarks-readme.md)). On M1 and M2 the worst-case register use of a shader sets occupancy for the whole dispatch. M3 and later Dynamic Caching softens this ([Apple tech talk 111375](../sources/apple-dynamic-caching-talk.md)). So on the M1 Pro, **build separate pipelines per number type and feature set** using function constants. A register-hungry floatexp or float-float path must never be compiled into the fp32 fast path. fp16 brings no ALU gain on M1 and is unusable for deltas, but it works for colouring outputs.

The watchdog is the hard constraint. Community reports put it at about 5 s **per command buffer, not per dispatch**, with fence waits counting towards it. Repeated timeouts can get the device's access revoked ([MLX issue #3302](../sources/mlx-watchdog-issue.md); [MTLCommandBufferError](https://developer.apple.com/documentation/metal/mtlcommandbuffererror-swift.struct/code.md)). Fraktaler 3 hits the same wall with OpenCL: bigger tiles are faster (1m34s versus 3 min for 960×1080 versus 128×128 tiles), but too-large tiles or step limits trigger OS timeouts ([Fraktaler 3](../sources/fraktaler-3-site.md)). The answer is a resumable kernel. Per-pixel state (delta, scale exponent, n, m, derivative, interior flags) lives in a buffer, each dispatch advances live pixels by an iteration budget, and command buffers carry about 10 to 30 ms of work, tuned from `gpuStartTime`/`gpuEndTime`. After each chunk, compact still-running pixels with an atomic counter and dispatch the next chunk indirectly over only those pixels. This attacks SIMD divergence, where 32 pixels wait for the slowest. Persistent "while queue not empty" kernels are riskier on macOS than on CUDA, because there is no preemption. Unified memory lets the CPU write the next reference and skip table into a second shared buffer while the GPU renders from the first. The 5 s figure is not documented by Apple, and the iOS behaviour is unknown, so design to the chunked model from day one rather than tuning around a number.

### Per-pixel and image-level tricks, ranked by payoff

**Derivative interior detection** has the best ratio of payoff to effort. Track `der ← 2(Z+z)·der` and stop when `|der|² < 1e-6` (Chéritat's ε = 0.001; 0.1 gives errors near parabolic points). It costs about 2× per iteration but makes very large maxIter almost free. Without it, N = 10⁶ took 45 s in Chéritat's example ([Chéritat wiki](../sources/cheritat-mandelbrot-rendering.md)). It needs no history buffer and is float32-safe, because only |der| matters and Z+z is O(1). Brent periodicity checking needs a tolerance that float32 cannot resolve at depth, and cardioid/bulb tests are useless once you are deep. **Exterior distance estimation** comes next: `DE = 2|z|ln|z|/|der_c|`, with `der_c ← 2(Z+z)·der_c + 1` and the dual part initialised to the pixel spacing so it stays inside float32 range ([mathr 2021](../sources/mathr-deep-zoom-theory.md)). One derivative buys filament anti-aliasing without supersampling (`coverage = clamp(DE_px/1.414, 0, 1)`), slope or normal-map lighting from `u = z/der` ([Chéritat wiki](../sources/cheritat-mandelbrot-rendering.md)), and adaptive sampling triggers. Imagina's LA carries the same derivative through skip steps.

For colouring, the smooth count `μ = n + 1 − log₂(log|z|)` with bailout ≥ 256 is nearly free ([Inigo Quilez](../sources/quilez-smooth-iteration.md)). The trap at depth is that μ reaches 1e6 to 1e9 and a float32 loses the fraction. zoomasm stores N in split channels for this reason ([zoomasm](../sources/zoomasm.md)), so store a uint32 n and a float fraction. Colour in a separate pass from stored per-pixel data (n, f, DE, phase, flags), so palette changes never recompute the fractal. For anti-aliasing, the KF2+ and zoomasm practice is uniform jitter of about 1 px, accumulated over subframes with a gamma-correct resolve. KF's manual says uniform jitter "looks better" than Gaussian ([KF2+ manual](../sources/kf-manual.md)). Interactively, this becomes progressive accumulation: one sample per idle frame, reset on camera change. Each extra sample is just another delta against the same reference.

**Solid guessing is overrated on GPUs.** KF's guessing caused speckles, was disabled and later re-enabled behind a menu option, and gave only about 1.5× instead of 4× under OpenCL ([KF2+ manual](../sources/kf-manual.md)). Derivative interior detection already makes interior pixels cheap. If you add guessing, restrict it to tiles whose entire border is interior. Frame reuse pays off more for interaction. XaoS-style reprojection shows the previous frame's stored data at once ([Wikipedia: XaoS](../sources/wikipedia-xaos.md)), followed by coarse-to-fine recomputation prioritised at the zoom focus, with KF-style "reuse reference" so the orbit and table persist while the view stays inside them. For movies, the exponential-map strip method (render log-polar strips once, reproject per frame) is what zoomasm and Fraktaler 3 use. No standard auto-maxIter algorithm is published. KF's undocumented version drops maxIter too far on zoom-outs and leaves black regions ([KF2+ manual](../sources/kf-manual.md)). A statistics-driven rule with hysteresis (raise maxIter when undetected non-escaping pixels exceed a threshold, never lower it without margin) is my recommendation, not a sourced method.

| swift-mandelbrot | BLA + rebasing | Float → double-float → perturbation, Metal, iOS+macOS, "past 10^1000" | 2026, licence unstated ([swift-mandelbrot README (drquicksilver)](../sources/swift-mandelbrot-readme.md)) |

No neutral cross-renderer benchmark exists. FractalShark's author expects Imagina to "beat it on performance in the long term". No mature, maintained macOS-native deep zoomer showed up, though hobby Swift/Metal projects already cover the BLA-plus-rebasing basics. almondbread can stand out on two things that nobody ships on Apple hardware: Imagina-class LA/AT on Metal, and a published, reproducible benchmark set.

Among other formulas, integer-power Multibrot (binomial delta, BLA Jacobian pZ^(p−1)), Mandelbar/Tricorn (2×2 real BLA) and Burning Ship (laser blaster's `diffabs` delta, BLA radius capped by |X| and |Y|) are realistic. Burning Ship's "deep needle" locations need full floatexp iterations, which KF never learned to detect automatically ([mathr 2021](../sources/mathr-deep-zoom-theory.md)). Hybrids need one reference per phase. Non-integer powers do not reduce ([UF perturbation equations](../sources/ultrafractal-perturbation-equations.md)). No perturbation scheme was found for Nova/Newton (historical deep Nova zooms used brute-force 192-bit precision, [hpdz](https://www.hpdz.net/TechInfo/Convergent.htm)) or for Mandelbulb, so defer both. The proven way to make formulas cheap to add is Fraktaler 3's opcode model (sqr, mul, absx, absy, negx, negy, rot, add). Each opcode derives its perturbed step and Jacobian mechanically, and generated, branch-free kernels are compiled at runtime. In Metal that means emitted MSL specialised by function constants.

## Ranked implementation roadmap

The order below puts correctness tooling and the chunked GPU architecture before speed, because float32 failures are silent and retrofitting resumable kernels is painful. Each step should leave a working explorer.

> **Corrections after ingest (2026-10-14):** mathr's maintained deep-zoom page calls an earlier BLA validity check "nonsense"; the single-step radius quoted in this report is probably that one. Use the formula recommended in [Bivariate linear approximation (BLA)](../techniques/bla.md) (see its Contradictions section) and validate with the skip-off diff. Rebasing also appears to work for Nova, magnet and Newton formulas according to Fractal Zoomer's author ([Other formulas: feasibility of deep zoom](../formulas/others-feasibility.md)), which softens the "no scheme found" claim above. FractalShark's author name differs between sources ([FractalShark](../implementations/fractalshark.md)).

| Rank | Step | Why now | Done when |
|---|---|---|---|
| 1 | CPU reference orbit (GMP/MPFR, precision from zoom + width + guard bits) stored as float32 in a shared buffer; GPU float32 perturbation with **rebasing**; Chebyshev/max-abs norms in tests | core of everything; one reference, no glitch logic | matches a CPU double render to ~1e-25 spacing |
| 2 | **Resumable chunked kernel**: per-pixel state buffer, ~10–30 ms command buffers timed from GPU timestamps, compaction + indirect dispatch | watchdog and divergence; hard to retrofit | no timeouts at 1e7 iterations; UI stays responsive |
| 3 | Verification harness: CPU double/floatexp tile renderer, skip-off pixel diff, Pauldelbrot overlay, fixed benchmark locations | float32 errors are silent | CI-style diff per location and depth |
| 4 | **Derivative interior detection** + exterior DE (pixel-spacing-scaled derivative) + split (n, f) smooth count; separate colouring pass | cheap, makes huge maxIter affordable, unlocks AA and slopes | interior-heavy views stop at bounded cost |
| 5 | **mathr BLA tree**, ε = 2⁻²⁴, built on CPU per reference and framing | first big speedup; generalises to other formulas | skip-on vs skip-off diff clean; ≥10× at 1e5+ iterations |
| 6 | **Rescaled float32 deltas** with floatexp scale and full floatexp steps near \|Z\|≈0; floatexp per-coefficient BLA storage; separate pipelines via function constants | removes the ~1e-25 depth wall | renders 1e-300 and 1e-1000 locations correctly |
| 7 | Nucleus reference: atom-domain or ball-period detection + MPFR Newton; reuse reference across zooms; MT3-style threaded squaring; double-buffered reference/table | cuts reference cost from maxIter to period p | interactive zoom without per-frame reference recompute |
| 8 | Interaction: reproject the previous frame, coarse-to-fine refinement from the focus, progressive jittered AA accumulation, statistics-driven maxIter with hysteresis | perceived speed | instant feedback on pan and zoom |
| 9 | **Imagina-style LA + AT** for power-2 Mandelbrot (period-aligned stages, non-linear first step, derivative propagation), keeping BLA for other formulas | largest win at minibrot depths, 1e6–1e9 iterations | measurable win over step 5 on benchmark set |
| 10 | Float-float (2×f32 + exponent) mode under `.safe` math with a startup known-answer test | repair and verification for long-orbit rounding | artefact locations from step 3 render clean |
| 11 | Formulas via an opcode model: Multibrot → Mandelbar → Burning Ship (diffabs, matrix BLA) → hybrids (one reference per phase) → Julia | breadth | each formula passes the step 3 diff |
| 12 | Extras: exponential-map movie export, reference-orbit compression (iOS memory), DE-guided adaptive sampling, tile guessing only for all-interior borders | niche or iPhone-driven | as needed |

For the iPhone/iPad port, the same Metal kernels apply. The differences that matter are memory (skip tables at 1e7 iterations approach a gigabyte worst case, which makes FractalShark/Imagina-style orbit compression and Fraktaler's skip-level pruning relevant) and unknown watchdog and thermal behaviour. The chunked design in step 2 is what makes the port cheap.

## Conclusion

The research mostly changes priorities rather than adding algorithms. The mathematics of fast deep zoom has been stable since 2022. What separates a toy from a serious explorer is now numerical hygiene on a float32 GPU (norms that do not underflow, per-quantity exponents in skip tables, ε matched to 24 bits, verification against an oracle) and scheduling under a watchdog that kills long command buffers. Both are almondbread-specific problems that no existing renderer solves for you, because the serious renderers lean on fp64 (CPU, OpenCL) or CUDA.

The strategic opening is Imagina-class LA with the AT minibrot shortcut on Metal. It is the fastest known method, it is public only as AGPL C++ code and FractalShark's CUDA port, and nobody ships it on Apple hardware. Reaching it safely means building the boring layers first: rebasing, chunking, the diff harness, BLA and rescaling. Then LA becomes a measurable upgrade rather than a leap of faith. The open empirical question is how far plain float32 deltas hold up over 1e6+ iteration orbits. No source answers it, and almondbread's own benchmark set should be the first to publish that answer.
